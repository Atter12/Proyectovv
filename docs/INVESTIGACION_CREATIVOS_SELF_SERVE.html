Investigación aplicada · Producto + APIs

Self-serve de creativos rechazados: reemplazar TikTok Ads Manager desde Creativos (Holistic)

Proyecto: Proyectovv / módulo Creativos
Periodo: septiembre 2026
Enfoque: review Smart+, motivos reales, preview, IA de corrección y apelación vía Marketing API

Resumen

El cliente de ecom Latam suele enterarse del rechazo de un anuncio solo en TikTok Ads Manager, con fricción alta y tickets a soporte. Esta investigación implementó un flujo self-serve en Creativos: descubrir rechazos Smart+, mostrar preview del video, motivos reales de policy, recomendación IA (no solo el tip genérico de TikTok) y, cuando aplica, apelación por API — priorizando corregir antes de apelar.

1. Problema de investigación

Cuando TikTok baja o rechaza un creativo, el usuario típico pregunta: “¿por qué me lo negaron?” y “¿qué hago?”. La respuesta estaba atrapada en Ads Manager (motivos largos, material UNAVAILABLE, sin preview usable en nuestra UI).

  • Hipótesis: con la Marketing API + IA se puede replicar (y mejorar) la experiencia de revisión sin abrir Ads Manager.
  • No-objetivo: suspensión de cuenta / BM (otro epic); aquí el foco es rechazo de material/anuncio.

2. Objetivos

  1. Listar solo los rechazos recientes del cliente (inbox accionable).
  2. Mostrar video/portada usable (no placeholder vacío).
  3. Exponer motivos de policy reales en español.
  4. Dar un “qué hacer” propio (IA), distinto del copy genérico de TikTok.
  5. Orden de producto: 1) corregir (subir otro) → 2) apelar solo si tiene sentido.

3. Metodología

3.1 Fuentes TikTok

Endpoint Uso en la investigación
/smart_plus/ad/review_info/ Estado UNAVAILABLE + reject_info (requiere include_reject_info: true)
/file/video/ad/info/ Portada y preview firmados (caducan; hay que refrescar)
/smart_plus/ad/appeal/ Misma cola de apelación que Ads Manager

3.2 Hallazgos técnicos clave

Síntoma Causa raíz Solución
UI decía “no hay más detalle” API sin extra_info_setting.include_reject_info Pedir reject_info + suggestion/specification
Miniatura en gris / “VIDEO” CSP bloqueaba tiktokcdn; URLs firmadas vencidas; http:// en portadas Abrir CSP + hydrate de media + HTTPS
“Qué hacer” = Ads Manager Se pegaba el tip genérico de TikTok IA con plan / ad text / appeal propios
Apelar de entrada CTA al mismo nivel que corregir Corregir primero; apelar secundario + confirmación

4. Caso observado (cuenta de prueba)

En anuncios Smart+ con status UNAVAILABLE, al pedir include_reject_info aparecieron motivos reales, por ejemplo:

  • Sector prohibido — pérdida de peso / metabolismo / quema de grasa (landing + creativo).
  • Flags de contenido “sexual/sugerente” que en gimnasio pueden ser falso positivo.

Conclusión de producto: en sector prohibido apelar casi no gana; la vía útil es video/texto nuevos sin esas claims. En falso positivo sexual, sí tiene sentido apelar con texto argumentado.

5. Flujo resultante (Creativos)

Descubrir rechazos Smart+ (TTL) → Hydrate: media fresca + motivos reales → Card: preview (zoom + sonido) · por qué · qué hacer (IA) → CTA 1: Subir video corregido → CTA 2 (opcional): Apelar si TikTok se equivocó (confirmación con el texto exacto enviado por API)

6. Resultados (antes → después)

Dimensión Antes Después
Motivo “Material no disponible” Policy real (peso, sexual, landing…)
Preview Placeholder vacío Portada + lightbox con audio
Acción Tip genérico / confusión Plan IA + texto sugerido + orden corregir→apelar
Apelación Solo en Ads Manager Self-serve vía API (misma cola)
Soporte Tickets “¿por qué me rechazaron?” Cliente ve y actúa en Creativos

Estado Prototipo usable en producción (main); iterativo, pero ya en la dirección deseada.

7. Limitaciones

  • URLs de preview firmadas caducan: dependen del refresh en cada carga.
  • QPS de TikTok: hay que paginar / sleep en sync masivo.
  • Apelar no modifica el creativo; si la policy es dura (sector prohibido), no “gana” sola.
  • La IA no debe inventar categoría de producto; usa cuenta / motivos / texto real.

8. Conclusiones

  1. Sí se puede acercar (y en parte superar) Ads Manager para el caso “video rechazado” desde Creativos.
  2. El valor no está en copiar el tip de TikTok, sino en traducir el rechazo a una acción (corregir vs apelar).
  3. La investigación confirma: dato API incompleto + CSP/media + UX de CTAs eran los tres bloqueos principales.

9. Próximos pasos (investigación / producto)

  • Cachear portadas en storage propio (menos dependencia de firmas TikTok).
  • Medir tasa: corrección subida vs apelación vs re-rechazo.
  • Separar aún más “cuenta suspendida” vs “creativo rechazado” en la narrativa al cliente.
